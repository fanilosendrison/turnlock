## 2026-09-03 delegation-target review

- [ ] [major] `src/bindings/target.ts` (+ `src/engine/delegation-reemit.ts`, `src/engine/shared.ts`, `tests/bindings/target-validation.test.ts`, `tests/engine/delegation-retry-target.test.ts`, `tests/e2e/legacy-delegation-target-compat.test.ts`, `docs/adr/0001-logical-delegation-targets.md`, `docs/architecture/delegation-model.md`) — a legacy manifest v2 worker name can be migrated and durably serialized on retry attempt N, then rejected on retry attempt N+1. Failure mechanism: manifest v2 allowed arbitrary non-empty `worker` strings; `resolveManifestTarget()` deliberately preserves a v2 worker name byte-for-byte when migrating (v2 imposed no naming constraints); the first retry rewrites the delegation as manifest v3 with `target = { kind: "worker", name: legacyWorker }`; from then on the stored manifest is a v3 manifest and every subsequent re-emission validates its target against the NEW v3 constraints (`^[a-z][a-z0-9-]*$`, `MAX_WORKER_NAME_LENGTH`). A historical name such as `Commit Msg [old]!` therefore follows: attempt 1 → migrated and emitted successfully as v3; attempt 2 → the SAME immutable logical target is rejected as invalid. This violates the invariant that the logical target is stable and retryable across attempts, and means a target can become invalid solely because Turnlock serialized it into the newer manifest format. A future fix must first decide and document the correct invariant — do NOT assume the answer is to normalize or reject legacy names; at least these options must be reasoned about: (A) separate validation of newly-authored worker targets from already-accepted durable targets (validate at authoring time only, never re-validate an accepted durable target); (B) relax/remove worker-name syntax restrictions if worker names are purely logical identifiers; (C) encode provenance/legacy compatibility so a successfully migrated durable target remains valid on all future retries; (D) another solution preserving both durability and deterministic replay. Required regression proof: an actual multi-retry scenario with a legacy name that violates the new v3 syntax — `v2 worker = "Commit Msg [old]!"`, attempt 0 → malformed/transient result, attempt 1 → re-emitted successfully as v3, attempt 1 result malformed/transient, attempt 2 → must behave consistently with the accepted logical target. Completion criteria: a test proves a target cannot be valid at attempt N and become invalid at attempt N+1 solely because of the manifest-format upgrade; ADR-0001 and docs/architecture/delegation-model.md are updated to state the decided invariant. (durability / correctness)
