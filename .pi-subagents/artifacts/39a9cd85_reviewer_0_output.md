## Review
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:428-430,443-445`: The launcher is spawned before the `"launcher-started"` state/PID is durably recorded. A crash in that window leaves `"dispatch-intent"` while the detached launcher runs; retrying the key spawns a second execution group.
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:803-813`: Stale-lock removal is an unchecked `unlink`. Another contender can replace the stale lock between `readLockFile` and `unlinkSync`, allowing this process to delete a valid holder’s lock and create concurrent writers.
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:516-522,191-192`: `readJobResult` updates `registry.json` after an unlocked read, contradicting the single-writer requirement. Concurrent result reads/reconciliation can overwrite each other’s job or launch-state updates.
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:603-616`: Retention deletes files before durably recording each acknowledgment. A crash after deletion leaves the registry unacknowledged; retry revalidation requires the now-missing file and cannot satisfy the stated idempotency guarantee.
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:159-166,558-560,590-594`: Stopped jobs are terminal without a result commitment or result file, yet retention requires every terminal job to supply a matching commitment and on-disk file. Failed jobs caused by oversize/binary output have the same gap (`740-746`). Such launches cannot be fully acknowledged or cleaned.
- **Blocker** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:484-492,562-567,1118-1122`: Launcher identity is only a PID. Same-boot PID reuse is explicitly possible, so inspection can treat an unrelated process as the launcher and `stopLaunch` can signal it. The lock nonce is not applicable to launcher identity.
- **High** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:410-419,434-437,721-724`: Target validation requires `allocationId` to match a launch namespace before I/O, but the namespace’s `dependencyExecutionId` is generated only afterward. A caller cannot construct a valid target under this ordering.
- **High** — `specs/working/proto-cdd-spec-turnlock-integration-v2.md:562-573,687-699`: A crash after durable stop intent but before signaling/finalization has no recovery transition. `inspectLaunch` only reconciles dead launchers; a live launcher with `stopRequestedAtEpochMs` remains running indefinitely unless another caller replays `stopLaunch`.
